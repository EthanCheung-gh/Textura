# 周报 / 月报 / 季报：视觉与交互走查清单

执行者：1 名熟悉本项目的开发或 QA，在装了 Node 22+、Chrome 稳定版与 Rust/Tauri 工具链的本机上，按「浏览器模式 + Tauri 桌面模式」双环境逐条执行；预计 90–120 分钟（第 7 组需要可用的大模型网关，另加 20 分钟）。

## 怎么用这份清单

- 每条都是「操作 → 预期 → 失败判定」三段式，逐条判定，只有三种结论：通过 / 失败 / 阻塞。
- 标 `（可脚本化）` 的条目可以用 DevTools 控制台或 `scripts/qa/` 下的 CDP 脚本自动断言，其余靠肉眼。
- 先读这一段模式差异，再开始执行：复制 Markdown 在浏览器与桌面模式都可用；下载 `.md` 在浏览器可靠落文件，在 Tauri 桌面模式可能完全没有反应（已知边界）；工作区导入 / 导出在 Tauri 走系统文件对话框，在浏览器走下载与文件选择框。
- 执行中不要改代码、不要改配置默认值、不要 git 提交；发现失败按第 12 组的方式记录。

## 10. 已知不可自动化 / 本轮明确不验

以下五项本轮不作为判定项，只需要在记录表里备注一句「不验」，不给通过结论：

- 真实网关的 CORS 白名单策略：依赖外部服务配置，本轮只用「不允许直连的网关」验证文案分支。
- 剪贴板权限的跨浏览器差异：只在 Chrome 稳定版验证「复制 Markdown」，其他浏览器与桌面 webview 的权限弹窗不展开。
- 像素级视觉对比：本轮只做「不裁切、不重叠、不撑破」的结构性判断，不做基线截图 diff。
- 跨平台字体与行高差异：只在当前执行机器上验证，Windows / Linux 的字体回退差异不在本轮范围。
- 移动端窄屏（< 768px）：产品非目标场景，本轮最低只到 1024×720。

**桌面端 AI 已不是「不验」项**：桌面端请求已改走 Rust 代理通道（`ai_proxy`，`reqwest` + `rustls`），由宿主进程发出，不再受 webview 的 CSP `connect-src` 与网关 CORS 限制，因此 AI 请求不会被拦截。桌面模式应照常执行 AI-01 / AI-02 / AI-05 / AI-06 / AI-07 / AI-11；浏览器模式仍走 `fetch` 直连，单独保留 CORS 分支（AI-08）。
     已知边界：代理使用内置 webpki 根证书（不读系统 / 企业 CA），企业 MITM 网关在桌面端会表现为「无法连接模型网关」，属预期现象不记缺陷；桌面端 AI-06 的超时由 Rust 与前端定时器共同判定（见第 7 组）。

## 12. 失败处理约定

- 每条失败在记录表「实际」列写一句客观现象，再补一段最小复现，落到 `实际` 列下方或独立的备注区，不要另建散落文件。
- 最小复现必须包含：操作步骤、视口尺寸与缩放比例、主题（浅色 / 深色）、模式（浏览器 / Tauri 桌面）、浏览器或 Tauri 版本、系统版本、数据来源（演示数据 / 导入文件 / 手工造数）。
- 附一张截图（命名见第 11 组），涉及报错时再粘 Console 原文；粘之前确认里面没有 `sk-` 开头的密钥片段。
- 同一现象在多条编号下出现时只记一条失败，其余条目标注「同上，见 <编号>」，避免同一问题被重复计数。
- 判定为失败的条目**不要就地改代码、不要临时改配置绕过**；需要修复时另开任务，本轮只留证据。
